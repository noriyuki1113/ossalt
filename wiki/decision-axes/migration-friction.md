# 移行摩擦（Migration Friction）

## 一言定義

SaaS から OSS 代替に移行する際の総コスト。データ移行・設定再構築・チームの習慣変容・連携ツールの再設定を含む。

## なぜ重要か

代替ツールの機能比較だけでは移行の成否は判断できない。移行摩擦が高すぎると、代替ツールを導入しても実際に使われないまま元の SaaS に戻るケースが多い。特に「チームの習慣変容」は機能差よりも移行失敗の原因になりやすく、ossalt ではこれを正直に伝える必要がある。

移行摩擦を構成する要素：
- **データ移行**: エクスポート形式の対応・フィールドのマッピング・欠損リスク
- **設定再構築**: 自動化・テンプレート・権限設定の再作成
- **連携ツールの再設定**: Webhook・API・外部サービス連携の再構成
- **習慣変容コスト**: チームメンバーの再学習・UX の違いへの適応
- **外部共有の再設計**: 外部ゲスト・クライアントとの共有方法の変更

## この軸で差が出るツール群

**摩擦が比較的小さい**

| SaaS → OSS | 移行ツール | 主な摩擦 |
|---|---|---|
| Slack → Mattermost | 公式 Slack インポーター | Bot・連携アプリの再設定 |
| Jira → Plane | Plane の Jira インポーター | カスタムワークフロー・権限スキームの再構築 |
| Airtable → NocoDB | CSV エクスポート | リンクフィールド・自動化の再設定 |
| Asana → Vikunja | Vikunja の Asana インポーター | 繰り返しタスク・依存関係の再設定 |

**摩擦が比較的大きい**

- **Figma → Penpot**: `.fig` 形式のインポートは部分対応。デザインシステム・Auto layout は手作業が多い
- **Notion → AppFlowy**: データベースリレーション・テンプレートの互換性が限定的
- **Jira → Plane（複雑な設定あり）**: カスタムフィールド・ワークフロー・スクリーンの再設計が必要

## ossaltでの使い方

saas ページの「Core decision axes」→「Migration friction」で、移行のどの部分が難しいかを構造化して示す。単に「インポートツールがある」と書くのではなく、「何が移行できて何が移行できないか」を明示する。

ユーザーへの問いかけとして：
1. 今の SaaS をどれくらい使い込んでいるか（浅い使い方なら移行は楽）
2. チームの中で最もツールに依存している人は誰か（その人の移行コストが全体を決める）
3. 移行の締め切りはあるか（コスト削減目的なら段階的移行が現実的）
