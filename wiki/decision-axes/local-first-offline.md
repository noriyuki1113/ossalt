# ローカルファースト・オフライン性

## 一言定義

データの正本をサーバーではなくデバイス上に置き、ネット接続なしでも完全に動作することを設計の核とする考え方。「オフラインファースト」とも呼ばれ、接続時に同期するのではなく、**ローカルが常に最新でクラウドは補助**という逆転した設計思想を指す。

## なぜ重要か

Notion を筆頭とする SaaS ワークスペースは、サーバー依存の設計を採用しているため、ネット接続が不安定・低速・不可の環境では動作が著しく劣化する。移動中・地方・機内・VPN 環境・オンプレ前提の組織など、実際の業務シーンでオフライン性は無視できない要件になりやすい。

また、ローカルファーストはオフライン対応にとどまらず、**データ所有権・プライバシー・セルフホストのしやすさ**とも深く連動する。データをローカルに持つ設計は、クラウドサービスへの依存度を下げ、ベンダーロックインのリスクを減らす。

ossalt において、Notion 代替を検討するユーザーの代表的な pain_point である「offline-local-first」「data-ownership」「vendor-lock-in」の3つを同時に解消する軸として機能する。

## この軸で差が出るツール群

| ツール | ローカルファースト性 | 備考 |
|---|---|---|
| **Anytype** | 最強 | E2E暗号化＋P2P同期。オンデバイスストレージが正本 |
| **AppFlowy** | 強い | オフラインモードをネイティブ対応。ローカルDB＋同期設計 |
| **AFFiNE** | 強い | ローカルファースト設計。セルフホスト対応 |
| **Outline** | 弱い | サーバー（PostgreSQL）必須。オフライン動作非対応 |
| **Notion** | 弱い | クラウド依存。オフラインは閲覧のみで編集不可 |
| **Obsidian** | 最強（参考） | ファイルシステムベース。完全ローカル動作 |

### ローカルファーストの度合いのグラデーション

ローカルファーストは「あり / なし」の二値ではなく、以下のようなグラデーションがある：

1. **完全ローカル**: サーバー不要・同期なし（Obsidian の基本形）
2. **ローカルファースト + 任意同期**: ローカルが正本・クラウドは補助（Anytype・AppFlowy）
3. **クラウドファースト + オフラインキャッシュ**: サーバーが正本・オフライン時はキャッシュ（多くの SaaS）
4. **クラウド専用**: オフライン動作なし（Notion の一部機能）

ossalt では、ユーザーが「オフライン」と言うとき、**どのグラデーションを求めているか**を先に明確にすることが重要。

## ossaltでの使い方

### ユーザーの動機を分類する

「ローカルファーストが欲しい」という動機は複数の意図に分解できる：

| 動機 | 向く候補 |
|---|---|
| 移動中・機内で編集したい（UX の問題） | AppFlowy / AFFiNE |
| データを誰にも渡したくない（プライバシー） | Anytype |
| サーバーを自社で管理したい（ガバナンス） | AppFlowy / Outline（セルフホスト） |
| インターネット接続がない環境で使う（インフラ制約） | AppFlowy / Anytype |

### 比較ページへの組み込み

Notion 代替の比較では、この軸を「セルフホスト難易度」と組み合わせて説明すると効果的。「ローカルファーストである」と「セルフホストできる」は別の概念だが、ユーザーには混同されやすい。

- ローカルファースト = データの保存場所・設計思想の問題
- セルフホスト = インフラの運用責任の問題
