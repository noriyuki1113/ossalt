# ローカルファースト・オフライン性

## 一言定義

データをローカルデバイスに優先保存し、ネットワーク接続なしでも動作するかどうかの軸。データ所有権・プライバシー・可用性の三つを同時に規定する。

## なぜ重要か

SaaS からの脱出動機の中で「データを自分のデバイスに持ちたい」「オフラインでも使いたい」という需要は根強い。特に知識管理・ドキュメント系ツールでは、インターネット接続が不安定な環境での作業や、クラウドサービス障害時のリスクを避けたいニーズがある。

また、ローカルファーストであることはデータ所有権・プライバシーとも連動する。データがローカルにあれば、SaaS が突然終了しても・価格を上げても・利用規約を変えても影響を受けない。

ローカルファーストの程度を問う問い：
1. **オフライン動作**: ネットワーク接続なしで読み書きできるか
2. **データの保存場所**: デフォルトでローカルか、クラウドか
3. **同期の方向**: ローカル → クラウドか、クラウド → ローカルか
4. **ベンダーなしで使えるか**: サーバーなしでも機能するか

## この軸で差が出るツール群

**ローカルファースト寄り**
- **AppFlowy**: Rust 製コアでオフライン動作。データはローカルファイルとして保存。チーム同期はオプション
- **Anytype**: オンデバイス暗号化・P2P 同期。オフラインアカウント作成が可能
- **Inkscape**: ローカルアプリとして完全オフライン動作。クラウド依存なし
- **Obsidian（参考）**: Markdown ファイルをローカルに保存。Sync はオプション

**クラウド依存（セルフホストでローカライズ可能）**
- **Outline**: クラウド前提だがセルフホストで自社内に閉じることができる
- **Mattermost**: サーバー必須だが、セルフホストで社内 LAN のみに制限できる
- **NocoDB**: サーバー必須。ただし接続先 DB がローカルであればデータは手元にある

**クラウド前提（ローカル動作なし）**
- **Penpot**: ブラウザベース。デスクトップアプリ（Electron）版でも基本はサーバー接続が必要

## ossaltでの使い方

知識管理・ドキュメント系ツールの saas ページ（notion / asana）では、この軸を重要な分岐点として明示する。特に：
- 「データをクラウドに置きたくない」→ AppFlowy / Anytype
- 「オフラインで使いたい」→ AppFlowy / Inkscape（用途による）
- 「セルフホストで社内に閉じたい」→ Outline / Mattermost

「ローカルファーストである」と「セルフホスト可能」は別の概念として区別する。セルフホストはサーバーを自分で管理することであり、ローカルファーストはデバイス上にデータが存在することを意味する。
