# Anytype

## 一言定義

オブジェクトベースの知識グラフ型ワークスペース。ローカルファースト・E2E 暗号化・P2P 同期を設計の核に置き、「データを自分で所有する」個人・チームに向けた Notion 代替。

## Positioning

Anytype は「Notion のような万能ワークスペースを OSS に移す」というよりも、**データ所有権・プライバシー・オフライン性を根拠に SaaS から離れたい**ユーザーに向けた独自設計のワークスペースである。

ドキュメントをフラットに並べるのではなく、すべてのコンテンツを「オブジェクト」として扱い、型（Type）・関係（Relation）・コレクション（Set / Collection）でグラフ構造を作る。Notion の「ページとデータベースの組み合わせ」とは異なる概念モデルを持つため、Notion 移行というよりも「思考のリセットを含む乗り換え」に近い体験になる。

Any-Sync プロトコル（Apache 2.0）を使った P2P 同期とオンデバイス暗号化を採用しており、クラウドへのデータ転送を最小化する。自社サーバーへのセルフホストも公式に対応している。[Source](https://anytype.io/)

## 強み

- **ローカルファースト・オフライン動作**: デバイス上のストレージが正とみなされ、オフライン状態でも完全に機能する。Notion の「オフラインに弱い」という代表的な痛点を正面から解消している。[Source](https://anytype.io/)
- **E2E 暗号化 + P2P 同期**: データはオンデバイスで暗号化され、Any-Sync プロトコルを通じてデバイス間で直接同期される。クラウドサーバーに平文データが残らない設計。
- **オブジェクト・グラフ型データモデル**: ページ・タスク・人物・書籍など、あらゆるコンテンツに型と関係を付けてグラフ的に管理できる。Notion の DB よりも表現力の高い知識グラフを構築できる。
- **クロスプラットフォームネイティブアプリ**: iOS / Android / macOS / Windows / Linux のネイティブアプリが提供されており、Web 依存がない。
- **データ所有権の明示**: 「offline account creation」「on-device encryption」「data portability」を公式に訴求しており、SaaS への不信を持つユーザーの信頼を獲得しやすい。
- **Any-Sync プロトコルの公開**: 同期プロトコルが Apache 2.0 で公開されており、インフラ層の独立性が高い。

## 弱み・注意点

- **学習コストの高さ**: オブジェクト・型・関係という概念モデルが Notion とは大きく異なる。Notion ユーザーが「そのまま移れる」ツールではなく、再設計を前提にした乗り換えが必要。
- **アプリライセンスの複雑さ**: クライアントアプリは「Any Source Available License 1.0」という独自ライセンスで、MIT / Apache のような標準的 OSS ではない。商用利用・フォーク・再配布に制約がある点に注意が必要。
- **チーム協調機能の発展途上**: リアルタイム共同編集・細かな権限管理・チーム管理機能は Notion や Outline に比べると未成熟な部分がある（Spaces 機能で対応中）。
- **エコシステムの薄さ**: 外部連携（Slack / GitHub / Google Drive 等）はまだ少なく、ツールとの統合が前提の組織ワークフローには向かない。
- **データ移行の難しさ**: 独自のオブジェクトモデルへの移行は、Notion のエクスポートをそのまま取り込むような簡単さではない。
- **コミュニティ規模**: AppFlowy・AFFiNE と比べると GitHub スター数は少なく、日本語情報はさらに限られる。

## どんなユーザーに向くか

| ユーザー像 | 向く理由 |
|---|---|
| データ所有権・プライバシーを最優先する個人 | E2E 暗号化・オンデバイスストレージが設計の核 |
| 個人知識管理（PKM）を深く構築したい人 | オブジェクト型・関係グラフで高度な知識構造を作れる |
| オフライン・低速回線環境で使いたいユーザー | ローカルファーストで完全動作 |
| SaaS への依存そのものを排除したいユーザー | P2P 同期・セルフホスト・アカウント不要モードが選べる |
| Roam Research / Obsidian 的な思考グラフに興味がある人 | リンク・関係・型によるグラフ管理に親和性が高い |

Notion の「チーム全員で使う共同 Wiki」としての用途を主とする場合は Outline が、Notion に近い見た目・UX での移行を優先する場合は AppFlowy が、より適切な候補になる。

## セルフホスト難易度

**中〜高程度**。

- Any-Sync プロトコルの自己ホストには、複数のサービス（any-sync-coordinator / any-sync-filenode / any-sync-consensusnode 等）を構成する必要があり、Dockerベースではあるものの構成は複雑。
- 個人の「データを自分のデバイスで持つ」用途であれば、サーバー不要でローカル動作するため、セルフホストを必要としないケースが多い。
- チーム共有のためのセルフホストは技術的ハードルが高く、インフラ知識のあるエンジニアが必要。

## 日本語圏での採用状況

グローバルでは E2E 暗号化・ローカルファーストの文脈で熱心なユーザーコミュニティを持ち、Reddit / HN に定期的に言及が出る。ただし Notion ライクな移行候補として紹介されることは少なく、「データ所有権にこだわるユーザー向け」として位置づけられることが多い。

日本語圏では Zenn・個人ブログに少数の紹介記事があるが、AppFlowy に比べてさらに少ない。「Notion 代替」というより「Obsidian・Roam の代替」として関心を持たれるケースが目立つ。ossalt での検索流入も、セルフホストよりもプライバシー・ローカルファースト軸からが主体になると推定される。

## ossaltにおける推奨文脈

Anytype を推薦すべき文脈：

1. **「データを完全に自分でコントロールしたい」** — E2E 暗号化・オフライン動作・セルフホストが最も徹底されている候補。
2. **「個人知識管理（PKM）を深く作りたい」** — オブジェクト型グラフモデルは高度な知識管理に向く。
3. **「Notion の SaaS 依存そのものをやめたい（チーム共有よりも個人用途）」** — 個人ユースで最も強い選択肢の一つ。
4. **「Obsidian の次のステップを探している」** — ローカルファーストを維持しつつ、より豊かなデータ構造を求める場合。

Anytype を推薦しにくい文脈：

- Notion の見た目・UX をなるべくそのまま維持したい場合（AppFlowy の方が適切）
- チーム全員での共同 Wiki 整備が主目的の場合（Outline の方が適切）
- 外部サービス連携・ウィジェット・テンプレート共有の豊富さを求める場合
- 標準的な OSS ライセンスでないと採用できない組織
