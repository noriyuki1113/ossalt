# Zulip

## 一言定義

「ストリーム（チャンネル）+ トピック（スレッド）」の 2 階層構造を持つ独自設計のオープンソースチャット。Slack の代替というより、**非同期コミュニケーションの問題を根本から解決する別思想のツール**として位置づけると正確。

## Positioning

Zulip は Slack が持つ「メッセージが流れて埋もれる」「チャンネルが増えてカオスになる」という根本問題を、**トピック必須の 2 階層構造**で解決しようとしている。すべてのメッセージはストリーム（チャンネル相当）の中に必ずトピック（スレッド相当）を持つ必要があり、会話が自動的に整理される。

Dropbox・Akamai・Recurse Center など技術系組織での採用が多く、特に**非同期・分散チームでのコミュニケーション品質向上**を重視する組織で評価されている。Apache 2.0 ライセンスで完全 OSS。[Source](https://zulip.com/)

## 強み

- **情報が埋もれない構造**: トピック必須の 2 階層により、過去の会話を検索・参照しやすい。「あの話どのチャンネルだったっけ」が起きにくい。
- **非同期コミュニケーションに強い**: リモート・分散チームでのコミュニケーション整理に優れており、時差のあるグローバルチームで特に評価される。
- **Apache 2.0 ライセンス**: 完全 OSS で商用利用・フォーク・組み込みに制約なし。
- **強力な検索機能**: トピック構造により、過去の会話の検索精度が高い。
- **セルフホスト対応**: 公式の Docker / Ubuntu インストール手順が整備されている。
- **クラウド版の無料枠**: Zulip Cloud の Free プランは検索可能なメッセージ数が無制限（Slack と異なる）。

## 弱み・注意点

- **Slack からの移行摩擦が最大**: トピック必須の設計思想が根本的に異なるため、Slack に慣れたチームにとって学習コストが高い。「移行」ではなく「乗り換え」の覚悟が必要。
- **リアルタイムチャット文化との相性**: 即時性・雑談重視のチャット文化には向かない。非同期・情報整理重視の文化のチームに向く。
- **外部連携の少なさ**: Mattermost・Rocket.Chat と比べて App 連携が少なく、Webhook 実装が中心。
- **日本語情報の少なさ**: 3 候補中最も日本語情報が少なく、導入障壁が高い。
- **UIの独自性**: Slack・Mattermost・Rocket.Chat と異なる UI 構造を学ぶ必要がある。

## どんなユーザーに向くか

| ユーザー像 | 向く理由 |
|---|---|
| 非同期・分散チームで情報整理を改善したい | トピック構造が会話の整理に強い |
| Slack の情報流失・検索性の低さに本質的な不満がある | 根本設計が異なるアプローチ |
| オープンソース開発コミュニティ・技術系組織 | 採用実績が多く文化的に馴染みやすい |
| グローバル・時差のある分散チーム | 非同期コミュニケーションの設計に優れる |

Slack から「より Slack らしいもの」に移りたいなら Mattermost。Slack の問題を根本から変えたいなら Zulip。

## セルフホスト難易度

**中程度**。

- Python + PostgreSQL + Redis ベースの構成で、Mattermost の Docker Compose より設定が独特。
- 公式の Ubuntu インストールスクリプトが整備されており、Linux サーバーの知識があれば構築できる。
- アップデートは公式スクリプトで比較的容易。
- プッシュ通知は Zulip の PUSH 通知サービス（無料）または自前構成が必要。

## 日本語圏での採用状況

3 候補中最も日本語情報が少なく、認知度も低い。Slack 代替として検索した際にヒットしにくく、技術系コミュニティの一部で知られている程度。

グローバルでは非同期コミュニケーションを重視する技術系組織・オープンソースプロジェクトでの採用が多い。日本でも同様の文化を持つエンジニアチームに刺さる可能性があるが、現状は認知度が最大の障壁。

## ossaltにおける推奨文脈

Zulip を推薦すべき文脈：

1. **「Slack でメッセージが流れて重要な情報が埋もれる」という本質的な不満がある** — トピック構造がこの問題を根本解決する。
2. **「非同期・分散チームでのコミュニケーション品質を上げたい」** — 設計思想が非同期に最適化されている。
3. **「Apache 2.0 の完全 OSS が必要」** — 3 候補中ライセンスが最もシンプル。

Zulip を推薦しにくい文脈：

- Slack に慣れたチームへのスムーズな移行が目的（Mattermost の方が適切）
- リアルタイムチャット・雑談コミュニケーション重視のチーム
- 日本語サポートを重視する非エンジニアチーム
