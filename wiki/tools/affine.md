# AFFiNE

## 一言定義

ドキュメント・ホワイトボード・データベースを単一の「KnowledgeOS」に統合する OSS。Notion ライクな文書管理に加え、Miro 的な無限キャンバスを同一環境で扱えることが最大の差別化点。

## Positioning

AFFiNE は「Write, Draw and Plan All at Once」を掲げ、テキストドキュメント（Paper モード）と無限キャンバスのホワイトボード（Edgeless モード）を同一ページ内で切り替えられる設計を持つ。Notion が「ドキュメント + データベース」の統合なら、AFFiNE は「ドキュメント + ホワイトボード + データベース」の統合であり、視覚的な整理・発想支援まで含めたワークスペースを求めるユーザーに刺さる。

ローカルファースト設計でオフライン動作に対応し、セルフホストも公式サポート。MIT ライセンスで完全 OSS であることも、AppFlowy（AGPL-3.0）や Outline（BSL 1.1）と比べた際の明確な強みになる。[Source](https://affine.pro/)

## 強み

- **ドキュメント × ホワイトボード統合**: 同一ページを「Paper モード（文書）」と「Edgeless モード（無限キャンバス）」で切り替えられる。Notion + Miro の組み合わせを一つのツールで実現したい場合に最有力候補。[Source](https://affine.pro/)
- **MIT ライセンス**: 完全に自由な OSS ライセンスで、商用利用・フォーク・組み込みに制約がない。OSS ライセンスを重視する組織に強い選択肢。
- **ローカルファースト・オフライン動作**: データをローカルに保持し、ネット接続なしで動作する。AppFlowy と同様にオフライン性を強みとする。
- **セルフホスト対応**: Docker ベースのセルフホスト構成が公式にサポートされており、データを自社インフラに置ける。
- **高い開発速度と注目度**: GitHub スター 4.5 万超（2026 年 4 月時点）。OSS workspace 系の中でも特に成長率が高く、リリース頻度も高い。[Source](https://github.com/toeverything/AFFiNE)
- **豊富なブロックタイプ**: テキスト、コード、テーブル、データベース、埋め込み、図形、付箋など多彩なブロックをドキュメント / キャンバス上で扱える。

## 弱み・注意点

- **機能の成熟度**: 開発が急速で機能追加が多い反面、安定性・完成度にばらつきがある。本番業務への展開は十分な検証が必要。
- **チーム協調機能**: リアルタイム共同編集は対応しているが、権限管理・チーム管理・SSO などエンタープライズ向け機能は発展途上。
- **データベース機能の深さ**: Notion の高度なリレーション・ロールアップ・formula に相当する機能は未実装または不完全な部分がある。
- **ホワイトボード特化ではない**: Miro・FigJam の代替として使う場合、専用ツールの操作性・機能セットには及ばない部分もある。
- **日本語ドキュメント・コミュニティ**: 公式ドキュメントは英語中心。日本語情報は他の候補と同様に限られる。
- **セルフホストの複雑さ**: セルフホスト版は機能制限があり、完全な機能を使うにはクラウド版が必要になるケースがある（ロードマップ依存）。

## どんなユーザーに向くか

| ユーザー像 | 向く理由 |
|---|---|
| ドキュメントとホワイトボードを行き来して考えたい人 | Paper / Edgeless の切り替えが独自の強み |
| Notion + Miro の組み合わせを一本化したいチーム | 両方の機能を同一環境で持てる |
| MIT ライセンスの完全 OSS が必須の組織 | AppFlowy / Outline より制約が少ない |
| 視覚的な整理・マインドマップ的な作業を重視するユーザー | Edgeless キャンバスが発想支援に向く |
| 最新 OSS workspace を試したい技術感度の高い個人・チーム | 開発速度が高く、新機能が頻繁に追加される |

チーム全体での安定した wiki 運用が主目的なら Outline、Notion に近い体験での移行が優先なら AppFlowy が、より確実な選択になる。

## セルフホスト難易度

**中程度**。

- Docker Compose ベースのセルフホスト手順が公式に提供されており、基本的な構成は構築できる。
- ただし AFFiNE のセルフホスト版はクラウド版に比べて機能が制限される場合があり、最新機能はクラウド版先行というパターンが続いている。
- データ同期・リアルタイム共同編集のためのサーバー側コンポーネントが必要で、完全なローカル専用運用とは別に設計が必要。
- アップデート頻度が高いため、セルフホスト版のメンテナンスコストは他候補より高くなりやすい。

## 日本語圏での採用状況

グローバルでは GitHub スター 4.5 万超と高く、ProductHunt や HN でも高評価を受けた記録がある。「Notion killer」として注目された時期があり、OSS workspace 系の中でも知名度は高い。

日本語圏では Zenn に複数の紹介記事があり、AppFlowy と並んで「Notion 代替 OSS」として検索でヒットしやすい位置にいる。ただし実際の業務導入事例はまだ少なく、個人ユーザーによるお試し・評価段階が中心と見られる。ホワイトボード機能への関心と、MIT ライセンスへの好意的な反応が目立つ。

## ossaltにおける推奨文脈

AFFiNE を推薦すべき文脈：

1. **「Notion とホワイトボードツール（Miro 等）を両方使っていて一本化したい」** — ドキュメント × キャンバス統合が最大の差別化。
2. **「MIT ライセンスの完全 OSS が必要」** — AppFlowy（AGPL）や Outline（BSL）より制約が少ない。
3. **「ローカルファーストで視覚的なワークスペースを作りたい」** — Edgeless モードの独自性が刺さるユーザーに。
4. **「OSS workspace の中で最も活発に開発されているものを使いたい」** — スター成長率・リリース頻度ともに高い。

AFFiNE を推薦しにくい文脈：

- 安定性・成熟度を最優先する本番業務環境（開発スピードの裏返しとして破壊的変更がある）
- チーム全体での長期的な wiki 運用が主目的（Outline が安定している）
- Notion のデータベース機能（リレーション・formula）に強く依存している場合
- ホワイトボード専用として使いたい場合（Miro・FigJam の代替にはなりきれない）
